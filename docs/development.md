# 開発ガイド

## プロジェクト概要

Kagutsuchiは、C++とVulkanを使った物理シミュレーション基盤です。再利用可能なライブラリ（`lib/`）と、それらを利用する複数のアプリケーション（`app/`）で構成します。

## ディレクトリと構成ルール

- 各ライブラリは `lib/<module>/` に配置し、独立したCMakeターゲットとして定義します。
- 公開ヘッダーは各モジュールの `include/` に配置します。例: `lib/physics/include/kagutsuchi/physics/`。
- 実装ソースは各モジュールの `src/` に配置します。
- 各アプリケーションは `app/<application>/` に配置し、独立した実行ターゲットとして定義します。
- モジュールやアプリを追加したら、対応する親 `CMakeLists.txt` から `add_subdirectory()` で登録します。
- 共通のCMake補助ファイルは `cmake/`、設計資料は `docs/` に配置します。
- アプリケーション固有の設計・仕様資料は `app/<application>/docs/` に配置します。各アプリの `docs/README.md` を入口とし、文書の用途と読み順を記載します。
- テストは対象モジュールの `lib/<module>/tests/` に配置し、そのモジュールのCMake設定から登録します。

### ドキュメントの更新方針

- ルートの `docs/` には、プロジェクト全体に適用する設計・開発方針を記載します。アプリ固有の仕様を重複して記載せず、必要に応じて該当アプリの文書へリンクします。
- アプリの `docs/` では、現在有効な設計・仕様、今後の作業、過去の設計判断をそれぞれ別の文書として管理します。標準の構成は `README.md`（入口）、`design.md`（現在の設計）、`roadmap.md`（未完了の作業）、`decisions/`（重要な設計判断の記録）です。規模に応じて必要な文書だけを作成します。
- `README.md` は文書の役割と読み順を案内する索引とし、詳細な仕様の複製を避けます。設計・仕様の正本は一つに定め、他の文書から参照します。
- `design.md` は現在の実装と合意済みの仕様を記載し、変更時に更新します。未決定の提案や未実装の事項は、その状態が分かるよう明記します。
- `roadmap.md` には未着手・進行中の作業を記載し、完了した項目は取り除きます。長期的に経緯を残す必要があるものは決定記録へ移します。
- `decisions/` には、将来の変更時にも背景が役立つ重要な判断だけを記録します。各記録には背景、検討した選択肢、決定、影響を簡潔に記し、後から判断が変わった場合は旧記録を削除せず、新しい記録から置き換え先を示します。
- 仕様変更時は、該当する正本と関連する索引・ロードマップ・決定記録を確認し、実装と文書の食い違いや古い説明を残さないようにします。

## ビルド

CMake 3.24以降、Ninja、およびC++20対応コンパイラを使用します。標準の構成とビルドには次を使います。

```sh
cmake --preset ninja
cmake --build --preset ninja
```

アプリケーションは既定で有効です。モジュールのテストは `KAGUTSUCHI_BUILD_TESTS` オプションが有効な場合に構成し、CTestへ登録します。

## 設計・変更時の方針

- モジュール間の依存は必要最小限にし、物理計算とVulkan固有処理の責務を分けます。
- 新しい依存ライブラリやツールを導入するときは、CMake設定とREADMEの必要環境・手順を合わせて更新します。
- sandboxのビルドにはVulkan SDKが必要です。開発時のValidation Layersは `-DKAGUTSUCHI_SANDBOX_VALIDATION_LAYERS=ON` で有効化できます。
- sandbox 固有の実装状況と未完了作業は [`app/sandbox/docs/README.md`](../app/sandbox/docs/README.md) から確認します。

## C++ コーディング規約

C++ ソースの命名、書式、依存関係、安全性に関する規約は [`cpp-style-guide.md`](cpp-style-guide.md) を参照してください。

C++ の書式整形には `clang-format` を使います。リポジトリルートから次を実行すると、C++ ファイルを整形できます。

```sh
clang-format -i path/to/file.cpp path/to/file.hpp
```

`.clang-format` の設定を変更した場合や `clang-format` を導入・更新する場合は、利用するバージョンで設定が認識されることを確認してください。
